## Core Tables

### businesses
Top-level tenant. `code` is unique globally (e.g., `TLC`). `settings` JSONB holds:
- `allow_cash_refund` (bool)
- `exchange_window_days` (int)
- `base_currency` (str)
- `accepted_currencies` (array)
- `receipt_header` (str)
- `label_template` (str)

### branches
Physical locations of a business. `is_default` marks the main branch. Cross-tenant FKs are enforced via `UNIQUE(business_id, id)`.

### profiles
One row per Supabase auth user. `id` = `auth.users.id`.

### business_members
Maps a profile to a business with a `user_role`. Optional `branch_id` pins a staff member to one branch. `max_discount_pct` caps their discount authority.

## Product Model

### products
`sku_prefix` + variant options → variant SKUs. Holds `default_sale_price` (the list price for all variants unless overridden). `tax_rate` is stored but TLC treats all prices as tax-inclusive.

### product_variants
One row per sellable SKU. `sale_price_override` overrides the product default. `business_id` is trigger-populated from `products` — callers cannot set it.

### variant_cost_pools
**Per (business, branch, variant).** Holds:
- `on_hand_qty` — total units owned (ALL buckets: sellable + quarantine + damaged)
- `total_value_base` — TRY-denominated total cost value
- `average_cost_base` — `total_value_base / on_hand_qty` (GENERATED)

Constraints: `qty ≥ 0`, `value ≥ 0`, `qty = 0 → value = 0`.

Only `fn_post_to_cost_pool` (SECURITY DEFINER) may write to this table.

## Inventory Ledger

### inventory_movements
INSERT-only. Each row records one stock movement:
- `bucket` — `sellable | quarantine | damaged`
- `quantity` — signed integer (positive = in, negative = out); `CHECK (quantity <> 0)`
- `reason` — enum (`movement_reason`): `purchase_receipt`, `sale`, `return_from_customer`, `transfer_out`, `transfer_in`, `inventory_adjustment`, etc.
- `unit_cost_snapshot` — cost at time of movement (nullable for outbound at MWA)
- `reference_id / reference_type` — link back to the source document

Current stock per bucket = `SUM(quantity) WHERE variant_id=? AND branch_id=? AND bucket=?`

### transfer_held_inventory
Floating cost carrier while stock is in transit between branches. One row per (transfer, variant). Holds `carried_total_value_base` — the exact TRY value deducted from the source pool. Cleared implicitly when transfer is received (received_at set).

## Sales Model

### sales
`client_transaction_id` — UUID sent by the POS device for idempotency.  
`idempotency_key_hash` — SHA256 of the full request payload; detects retries with changed content.  
`sold_by` — always `auth.uid()` (never client-supplied).

### sale_items
`line_total` = `quantity × unit_price_at_sale` (GENERATED). No cost columns here.

### sale_item_costs ← manager+ RLS
`unit_cost_at_sale` — MWA at time of sale.  
`line_cost` — `unit_cost_at_sale × quantity`.  
Only managers and owners can SELECT this table.

### sale_costs ← manager+ RLS
Aggregated cost and margin at sale level. One row per sale.

### sale_payments
One row per payment tender. Holds `currency`, `amount_original`, `fx_rate_id`, `amount_base` (GENERATED).

---

## Returns Model

### returns
`original_sale_id` — FK to `sales`. No `status` column — a return is always considered completed on creation.  
`return_number` — business-scoped sequential number (generated by RPC).

### return_items
`unit_cost_at_sale` — copied from `sale_item_costs` by the RPC (NEVER from client).  
`condition` — `resellable | damaged | missing`.  
All returned stock enters `quarantine` bucket.

---

## FX Rates

### fx_rates
INSERT-only. `is_current = true` for the active rate per (business, rate_date, currency). Corrections: `rpc_set_fx_rate` deactivates the old row (`is_current = false`, sets `superseded_by`) and inserts a new current row. No UPDATE to rate amounts ever.

Supported: `GBP`, `EUR`, `USD`. TRY needs no rate (always 1.0).

## Composite Type

### t_cost_pool_result
```sql
CREATE TYPE t_cost_pool_result AS (
  unit_cost_used       NUMERIC(12,4),   -- PRE-movement MWA (or p_unit_cost_base for receipts)
  value_delta_base     NUMERIC(14,4),   -- signed change applied to pool value
  new_on_hand_qty      INTEGER,         -- pool qty after movement
  new_total_value_base NUMERIC(14,4)    -- pool value after movement
);
```
Returned by `fn_post_to_cost_pool`. The `ABS(value_delta_base)` is stored as `carried_total_value_base` in transfers.
